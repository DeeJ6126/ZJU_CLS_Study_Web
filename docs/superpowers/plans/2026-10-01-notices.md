# Public Notices Implementation Plan

> **For agentic workers:** Use subagent-driven-development to implement this plan task-by-task.

**Goal:** Add a public notice directory with administrator-only maintenance, then deploy the verified same commit locally and on the server.

**Architecture:** Separate public `#notices` from private account `#notifications`. Store notice records and attachment metadata in the existing content SQLite database, with files under the existing upload directory. Shared API clients, category config and safe Markdown rendering serve public and admin views.

**Tech Stack:** Vue 3, plain CSS, Node HTTP/SQLite, Node tests and Playwright.

## Approved Scope

- Public search and paginated lists, category/major/cohort/deadline filters, pinned-first ordering.
- Details show summary, publisher, publication date, target audience, deadline, Markdown body, original source and attachments.
- Administrator list/search, draft creation, editing, preview, publish, pin, archive, attachment upload and removal.
- No public applications, comments or submissions. No fabricated real notices seeded online.
- Categories: awards, scholarships, aid, academic, general. Majors and cohorts are optional; empty means unrestricted.
- Publication date is a date; deadline uses Shanghai time. No deadline means no forced expiry state.
- PDF, DOCX, XLSX attachments up to 25 MB, administrator-only writes and published-only public downloads.
