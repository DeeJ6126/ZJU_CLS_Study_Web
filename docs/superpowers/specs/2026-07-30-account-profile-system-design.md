# 账号与个人主页系统设计

## 目标

在现有 CC98 与浙大邮箱账号系统上增加严格的学号邮箱规则、可维护用户资料、CC98 换绑、公开个人主页、用户搜索和本人帖子管理，同时保持课程、刷题、管理员审核、评论、收藏及现有课程路由不变。

本阶段面向小规模站点，继续使用现有 Node 服务、SQLite 和本地上传目录，不引入独立身份服务、对象存储、状态管理器或路由库。

## 账号身份规则

### 浙大邮箱

- 注册与登录界面固定展示 `@zju.edu.cn`，用户只输入学号部分。
- 学号部分只允许纯数字，不限定长度。
- 服务端始终重新拼接并验证完整邮箱，不能依赖前端限制。
- 新注册账号必须同时设置密码与全站唯一昵称。
- 邮箱身份不可换绑。
- 现有数字学号邮箱账号保持兼容。
- 若存在旧的非数字邮箱身份，数据库记录不删除，但普通学号登录界面不再接受该地址；管理员可在后续数据维护阶段处理。

### 昵称

- 邮箱账号的昵称长度为 2–20 个字符。
- 允许中文、英文字母、数字、下划线和短横线。
- 昵称按去除首尾空白后的值保存，并按不区分大小写的规范值执行唯一约束。
- 禁止控制字符、空昵称和系统保留名称。
- 邮箱账号可在个人主页修改昵称。
- 账号一旦绑定 CC98，昵称由服务端强制同步为 CC98 名字，不能手动修改。

### CC98 绑定与换绑

- 绑定或换绑必须在真实登录会话中完成。
- 请求必须包含当前账号密码和一个尚未使用的新 CC98 验证码。
- 新 CC98 名字不得已绑定其他账号。
- 换绑在单个数据库事务中释放旧身份、占用新身份并同步昵称。
- 原 CC98 名字在换绑后可供其他账号绑定。
- 换绑成功后撤销该用户除当前会话外的其他会话。
- 管理员白名单角色继续按当前策略维护；普通换绑不能借此绕过管理员角色规则。

## 用户资料与头像

`users` 增加随机公开 ID、昵称规范值和头像元数据。内部关联仍使用不可变的数据库用户 ID，公开路由只使用随机公开 ID。

所有登录用户均可上传头像：

- 接受 JPEG、PNG 和 WebP。
- 原始文件最大 2 MB。
- 同时检查扩展名、MIME 和真实文件头。
- 使用成熟图片处理库解码，裁切为正方形并输出最大 512×512 的 WebP。
- 重新编码时清除 EXIF 等原图元数据。
- 随机生成存储名，禁止路径穿越。
- 替换头像后删除旧文件。
- 文件由受控接口返回，并设置正确 MIME、缓存策略和 `nosniff`。

头像目录与内容 PDF 目录分离，通过环境变量配置持久化路径。游客继续使用默认头像。

## 个人主页

### 路由

- 本人入口：右上角账号面板中的“个人主页”。
- 公开路由：`#profile/#<publicId>`。
- 不向顶部学生导航增加新项目。
- 昵称变化不会改变公开主页地址。

### 公开视图

公开接口和页面只展示：

- 头像。
- 当前昵称。
- 该用户当前处于 `published` 状态的帖子。

公开视图不返回邮箱、CC98 绑定状态、角色、审核记录、待审核内容、被驳回内容或内部用户 ID。不存在或不可公开的用户使用统一的“用户不存在”结果。

有明确所有者的帖子在卡片和正文中显示所有者的当前昵称，并提供个人主页链接；
原投稿中的作者说明仍可保留在正文元数据中，但不作为账号身份。旧静态资料或无法确认
所有权的历史内容继续显示原作者文字，不生成个人主页链接。

### 本人管理视图

本人访问自己的主页时额外显示：

- 头像上传与替换。
- 昵称编辑；CC98 账号显示昵称锁定原因。
- 账号认证摘要。
- 待审核、已发布、被驳回和已下架四类帖子。
- 待审核内容编辑。
- 被驳回内容修改并重新提交。
- 已发布内容提交修订。
- 已发布内容立即主动下架。

不提供永久删除，以保留审核和操作记录。

## 帖子归属与修订

用户所有权只由后端用户 ID 决定，不再信任投稿表单中的作者文字。新投稿、审核通过后的内容记录和后续修订都保留原始所有者 ID。

内容库增加稳定的所有者字段，并为投稿记录增加：

- 投稿动作：新建或修订。
- 目标已发布内容 ID。
- 修订基于的版本时间或版本号。

修订流程：

1. 作者编辑已发布内容时创建待审核修订，原内容继续公开。
2. 管理员看到“帖子修订”标记及当前版本与拟修改内容。
3. 审核通过后，在事务中更新原内容并记录审核日志。
4. 审核拒绝后，原内容保持不变，修订进入被驳回状态。
5. 若原内容在审核期间被下架，批准修订只更新内容，不自动重新发布。

作者主动下架立即生效，并写入操作日志。重新发布仍需经过管理员审核。

## 首页用户搜索

首页共享搜索索引增加“用户”结果类型：

- 按昵称规范值进行包含匹配。
- 最多返回 5 个用户。
- 只返回公开 ID、昵称、头像地址和个人主页链接。
- 不允许通过邮箱、学号或 CC98 身份搜索用户。

用户结果与课程、资料、题库和活动结果使用现有紧凑搜索样式，不改变首页主要布局。

## 后端接口

公开接口：

- `GET api/profiles/:publicId`
- `GET api/profiles/:publicId/posts`
- `GET api/profiles/search?q=...`
- `GET api/profile-avatars/:storedName`

本人接口：

- `GET api/account/profile`
- `PATCH api/account/profile`
- `PUT api/account/profile/avatar`
- `DELETE api/account/profile/avatar`
- `PUT api/account/cc98`
- `GET api/account/posts`
- `PATCH api/account/submissions/:id`
- `POST api/account/submissions/:id/resubmit`
- `POST api/account/content/:id/revisions`
- `POST api/account/content/:id/archive`

接口继续使用 Cookie 会话。所有写接口执行同源 JSON 或专用文件请求检查，并在服务端验证资源所有权。

## 前端结构

- 新增独立 `ProfilePage.vue`，使用现有绿色页头、188px 左侧导航和紧凑内容布局。
- 新增资料、头像和本人帖子 API 客户端，组件只负责展示和发出事件。
- 账号弹窗的邮箱字段改为“学号输入 + 固定后缀”组合。
- 邮箱注册表单增加昵称字段；邮箱登录与找回密码继续只需学号和密码或验证码。
- 账号面板增加“个人主页”入口。
- 帖子作者链接和首页用户搜索统一使用公开用户模型。
- 移动端将左侧导航转换为已有的纵向可扫描布局，表格转换为列表。

## 迁移与兼容

- 启动时为现有用户幂等生成随机公开 ID。
- CC98 用户的昵称与当前 CC98 身份同步，并建立昵称规范值。
- 数字邮箱账号若尚未设置合格昵称，在本人主页显示一次性补全提示；完成前仍可登录和浏览，但不能新增投稿。
- 现有投稿根据 `submitter_id` 回填所有者。
- 现有已发布投稿根据其来源投稿或 `created_by` 回填所有者。
- 静态导入内容和无法确认所有者的历史内容保持无归属。
- 课程代码、课程 hash 路由、刷题配置、管理员路由、评论、收藏和点赞逻辑保持不变。

## 错误处理

- 学号、昵称、密码、验证码和图片错误返回明确字段错误。
- 昵称冲突返回 `409`，不暴露其他账号资料。
- CC98 绑定冲突或验证码错误使用一致的安全提示。
- 图片解码失败时不保留临时文件，也不覆盖旧头像。
- 修订发生版本冲突时返回 `409`，要求作者重新载入当前帖子。
- 后端不可访问时，公开课程内容仍沿用现有静态回退；个人主页明确显示暂时不可用，不伪造本地资料。

## 测试与验收

自动化测试覆盖：

- 学号字段只接受纯数字，并正确拼接固定邮箱后缀。
- 非数字别名无法注册、登录、找回密码或绑定。
- 邮箱昵称校验、不区分大小写的唯一性及并发冲突。
- CC98 昵称锁定、换绑事务、旧身份释放和其他会话失效。
- 头像格式、文件头、大小、重新编码、元数据清除、替换与删除。
- 公开主页只泄露允许字段，只显示已发布帖子。
- 本人帖子分类、所有权校验、修订审核、版本冲突和主动下架。
- 首页用户搜索不支持邮箱或学号查询。
- 旧账号、旧投稿和无归属静态内容迁移幂等。
- 现有账号、课程、刷题、资源、评论、收藏、投稿和管理员测试继续通过。

最终运行：

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run check
```

并在桌面与移动视口手工验证邮箱表单、头像上传、公开个人主页、本人帖子管理和管理员修订审核。
