# Security And Auth

## 当前状态

当前登录和认证是前端骨架，用于 UI 测试，不是真实安全系统。

已有测试用户：

- 游客
- CC98 认证者
- 邮箱认证者
- CC98 + 邮箱认证者
- 开发者

权限规则集中在：

```txt
src/services/authService.js
```

## 当前前端能力

- 游客可以浏览公开资源。
- 认证用户可以投稿、评论、收藏。
- 开发者可以接收投稿申请消息。
- 信箱、收藏、评论目前是前端模拟状态。
- CC98 验证码注册/认证第一版是前端 mock 原型：固定验证码暂存在 `src/data/config/cc98VerificationCodes.js`，匹配入口在 `src/services/cc98VerificationService.js`，本地状态暂存在 localStorage。
- CC98 前端原型状态只用于当前 UI 和权限模型演示，不提供真实安全能力。

## 禁止误解

- 不要把前端权限判断当作真实认证。
- 不要在组件里写安全决策。
- 不要把验证码、邮箱认证、CC98 认证写成纯前端逻辑。
- 不要在 Vue 组件中硬编码 CC98 mock 验证码。
- 不要把 CC98 前端 mock 验证码文案写成后端已经完成的真实认证。

## 未来真实后端

如果进入真实登录阶段，应新增后端或 `server/`，并实现：

- 用户表
- 验证码表
- 过期时间
- 限流
- session/cookie 或 JWT
- 投稿审核表
- 评论和收藏持久化

学校邮箱验证码需要 SMTP 或邮件服务。CC98 验证码认证需要后端校验，前端只展示状态。

当前 `cc98VerificationService.js` 是后续迁移到后端 API 的前端边界。真实后端阶段应由服务端保存验证码、处理过期时间和限流，并返回可信用户认证状态；前端只消费结果，不再持有验证码列表。

## 项目检查

- `npm run check:architecture` 会检查权限入口是否集中在 `authService.js`。
- 权限策略数据记录当前前端权限模型。
